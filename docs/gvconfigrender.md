# gvconfigrender - Template Rendering and Deployment

Render configuration templates with host/environment variables and deploy to fleet hosts using Jinja2.

## Aliases

- `render`
- `rr`

## Usage

```bash
gvconfigrender <command> [options]
```

## Commands

### render

Render a template locally.

```bash
# Render for a specific host
gvconfigrender render nginx.conf.j2 --host web1.example.com

# Render for all hosts in a role
gvconfigrender render nginx.conf.j2 --role web --output-dir ./rendered/

# Render with extra variables
gvconfigrender render nginx.conf.j2 --host web1 --var "port=8080" --var "workers=4"

# Output to stdout
gvconfigrender render nginx.conf.j2 --host web1 --stdout
```

**Options:**

- `--host`, `-H`: Target host for variable resolution
- `--role`, `-r`: Render for all hosts with this role
- `--output-dir`, `-o`: Output directory (creates per-host files)
- `--stdout`: Output to stdout
- `--var`, `-v`: Extra variable (key=value, can be repeated)

### deploy

Render and deploy template to hosts.

```bash
# Deploy to a host
gvconfigrender deploy nginx.conf.j2 /etc/nginx/nginx.conf --host web1.example.com

# Deploy to role with validation
gvconfigrender deploy nginx.conf.j2 /etc/nginx/nginx.conf \
  --role web \
  --validate "nginx -t"

# Deploy with backup
gvconfigrender deploy nginx.conf.j2 /etc/nginx/nginx.conf \
  --role web \
  --backup \
  --reload "systemctl reload nginx"
```

**Options:**

- `--validate`, `-v`: Validation command (runs before replacing)
- `--reload`, `-r`: Reload command (runs after replacing)
- `--backup`, `-b`: Create backup of existing file
- `--mode`, `-m`: File mode (e.g., 0644)
- `--owner`, `-o`: File owner
- `--group`, `-g`: File group
- `--yes`, `-y`: Skip confirmation

### vars

Manage template variables.

```bash
# Set global variable
gvconfigrender vars set global domain example.com

# Set role-specific variable
gvconfigrender vars set role:web upstream_port 8080

# Set host-specific variable
gvconfigrender vars set host:web1.example.com custom_setting value

# List all variables
gvconfigrender vars list

# Show variables for a host
gvconfigrender vars show --host web1.example.com

# Delete a variable
gvconfigrender vars del global domain
```

### template

Manage template library.

```bash
# Save template to library
gvconfigrender template save ./nginx.conf.j2 --name nginx

# List saved templates
gvconfigrender template list

# Show template content
gvconfigrender template show nginx

# Delete template
gvconfigrender template del nginx
```

## Template Variables

Templates have access to:

| Variable    | Description                             |
| ----------- | --------------------------------------- |
| `host`      | Host object with name, roles, env, tags |
| `hostname`  | Host hostname                           |
| `env`       | Host environment                        |
| `roles`     | List of host roles                      |
| `inventory` | Full inventory access                   |
| `global.*`  | Global variables                        |
| `role.*`    | Role-specific variables                 |
| `host.*`    | Host-specific variables                 |

## Example Template

```jinja
# {{ hostname }} - Generated by gvconfigrender
# Environment: {{ env }}

upstream backend {
    {% for h in inventory.by_role('app') %}
    server {{ h.hostname }}:{{ role.upstream_port | default(8080) }};
    {% endfor %}
}

server {
    listen {{ host.port | default(80) }};
    server_name {{ global.domain }};

    location / {
        proxy_pass http://backend;
    }
}
```

## Examples

```bash
# Render and preview
rr render nginx.conf.j2 --host web1 --stdout

# Deploy with validation
rr deploy nginx.conf.j2 /etc/nginx/nginx.conf \
  --role web \
  --validate "nginx -t" \
  --reload "systemctl reload nginx" \
  --backup

# Set up variables
rr vars set global domain example.com
rr vars set role:web upstream_port 8080
rr vars set role:web worker_processes auto

# Render for all web servers
rr render nginx.conf.j2 --role web --output-dir ./rendered/
```

## Exit Codes

- `0`: Success
- `1`: Template error or validation failed
- `2`: Deployment error
